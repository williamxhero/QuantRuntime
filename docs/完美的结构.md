# Strategy Workspace 与 Quant Runtime 的最终边界

从 0.2.0 开始，Strategy Workspace 与 Quant Runtime 不再是一个仓库里的两套重叠实现。

```text
Strategy Workspace（控制面）
  Strategy Package / request / snapshot / attempt / artifact / result
                              |
                              v
Quant Runtime（执行面）
  MarketHub + optional Qlib + one or more Nautilus formal legs
```

Strategy Workspace 是 durable source of truth：负责包注册、参数和 request.v2 验证、请求幂等、
SQLite 元数据、不可变 ArtifactRef、attempt/retry、publication 与 result.v2。Quant Runtime 只从
公开 `WorkspaceClient` / `WorkspaceWorker` 接口取包、取快照、登记运行身份并原子结束 attempt。

Quant Runtime 是深执行模块：`RuntimeExecutor` 一次性完成 capability resolution、MarketHub
输入校验、可选 Qlib discovery、Nautilus formal legs、comparison/agreement、native evidence 与
artifact lineage。它没有自己的 Workspace 数据库、schema 副本、package-admin 命令或策略目录。

## 四种拓扑

- `formal_only`：一个 formal leg，不运行 Discovery。
- `discovery_formal`：先生成 Qlib 原生研究证据，再独立运行一个 formal leg。
- `formal_comparison`：同一包、参数、快照上运行两个或更多独立 formal leg。
- `agreement_gate`：对声明的 scalar metric selectors 按绝对/相对容差做无 reference engine 的
  一致性判断；不通过时是有效 `rejected` 终态。

Discovery 是可选证据层，不拥有 formal 状态。Formal 策略只从 Nautilus 实际观察到的 bars
生成信号；Qlib future labels、candidate rows 或 target positions 不进入 `FormalRunInput`。

## 数据与复现

MarketHub 是唯一生产数据源。Reference snapshot 携完整 source/query 和冻结 revision，Runtime
在读 bars 后再次验证版本，默认不持久化 raw bars。Materialized snapshot 的 catalog、calendar、
coverage 与 partitions 全部是 Workspace ArtifactRef；Runtime 逐项 materialize、校验 hash/bytes、
coverage/order/duplicates 与 canonical input hash。

`request_id` 即 Workspace `run_id`，由 immutable request 决定。Runtime identity 进一步记录包、
参数、快照、拓扑、每个 adapter/engine 版本、config hash 和 read semantics。相同请求不重复执行；
失败只能显式 retry，并生成新的 attempt。

## Breaking cut

0.2.0 已立即删除 `discover`、`evaluate`、`golden-check`、candidate/formal manifest、公有 v1
models、内嵌 Workspace/schema 和 canonical momentum 策略副本。旧 runtime 数据不删除，但新
代码不读取，也没有兼容入口。Canonical momentum Strategy Package 已归 Strategy Workspace
所有；Quant Runtime 只保留明确标注的测试 fixture。
